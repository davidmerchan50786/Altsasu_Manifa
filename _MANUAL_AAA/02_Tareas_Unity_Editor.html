PROYECTO ALTSASU · MANIFA

MANUAL 2

Tareas en Unity Editor
(lo que el asistente no puede hacer)

Requiere: Unity 6000.3.10f1 + GPU. Tiempo estimado total: 1–2 jornadas.

0 · Por qué esto lo haces tú

El asistente trabaja sin Unity, sin GPU y sin pantalla. Todo lo que requiere el editor abierto (hornear, ver, asignar referencias visuales, build) es tuyo. Esta es la lista completa, ordenada.

1 · Abrir el proyecto por primera vez

  • Instala Unity 6000.3.10f1 exacto desde Unity Hub (si no, te convertirá assets y puede romper metadatos).
  • Abre la carpeta Altsasu_Manifa. La primera importación tarda (miles de assets); déjala terminar.
  • Si quitaste Cesium embebido (Manual 1), Unity lo descargará del registro: Window → Package Manager → comprueba "Cesium for Unity 1.23.2" sin errores.
  • Revisa la consola: 0 errores rojos. Warnings amarillos se toleran de momento.
Si ves errores de scripts al abrir, NO toques nada hasta que termine de compilar (barra inferior derecha). Muchos "errores" desaparecen al acabar la primera compilación.

2 · La escena principal

Escenas reales del juego: Assets/#Scenes/Alsasua_Main.unity y MenuPrincipal.unity.

  • Abre Alsasua_Main.unity.
  • Comprueba que existe un GameObject con SceneBootstrapper y otro con AltsasuCore. Si no, el mundo se autogenera al pulsar Play (el bootstrap crea lo que falte).
  • Pulsa Play. Debe: crear el terreno desde el DEM, generar edificios/calles desde el JSON OSM, y aparecer el jugador en Herriko Plaza.
  • File → Build Settings → añade MenuPrincipal (índice 0) y Alsasua_Main (índice 1) a "Scenes in Build".

3 · Terreno (DEM/LIDAR)

El relieve sale de Assets/AlsasuaData/dem_unity_1025.raw. Para máxima precisión usa el pipeline del Manual 3 y luego:

  • Con el terreno generado, ejecuta el menú del juego que sube precisión con LIDAR (GeneradorTerrenoUltraPreciso) si lo tienes en un menú de editor.
  • Pinta capas de terreno: SistemaTerreno lo hace por pendiente/altitud al arrancar; revisa que las Terrain Layers tengan texturas asignadas (hierba, tierra, roca, asfalto).
  • Ajusta Terrain → Resolution si va lento; 6×6 km es grande.

4 · NavMesh (IA y NPCs no andan sin esto)

El tráfico, multitudes y enemigos necesitan NavMesh horneado.

  • Window → AI → Navigation (o el paquete AI Navigation / NavMeshSurface).
  • Marca el terreno y los edificios como Navigation Static / añade NavMeshSurface al root del mundo.
  • Bake. En un mundo de 6 km esto tarda; ajusta agent radius/height al de tus NPCs.
  • Verifica que SistemaNavMesh/NavMeshBaker (portado de v2) encuentra la malla.
Para mundos grandes, hornea NavMesh por zonas (ya tienes GestorZonasAlsasua con 10 zonas) en vez de uno gigante: mejor rendimiento y bake más rápido.

5 · Iluminación y HDRP (el look "AAA")

  • Window → Rendering → Lighting: configura el Environment (HDRI Sky). Tienes HDRIs en Assets/HDRIs/.
  • Coloca un Volume global con el perfil HDRP (lo gestiona SistemaVolumenHDRP/SistemaPostProcesoAAA): exposición, tonemapping (ACES), bloom, ambient occlusion, motion blur, vignette.
  • Sol: un Directional Light controlado por SistemaAtmosfera (ciclo día/noche). Sombras a "High", contact shadows ON.
  • Lightmaps: para elementos estáticos, marca Static y hornea GI. Para 6 km, usa sobre todo iluminación en tiempo real + reflection probes en zonas clave (plaza, calles principales).
  • Coloca Reflection Probes en plaza, interiores y cruces importantes.
HDRP a 6 km es exigente. Si no llegas a 60 fps, baja calidad de sombras en lejanía, usa LODs agresivos (Manual 4) y streaming por zonas antes que bajar resolución global.

6 · Materiales y conversión HDRP

  • Tras importar assets nuevos (sobre todo de paquetes Built-in/URP), conviértelos: Edit → Rendering → Materials → Convert all built-in to HDRP, o usa ConversorMaterialesHDRP del proyecto.
  • Materiales rosas = shader incompatible → conviértelos.
  • Asigna las texturas de Assets/Textures_AAA/ (PBR: Albedo, Normal, ARM/AO, Displacement) a materiales HDRP/Lit.

7 · Tras un refactor de código (reasignar referencias)

Cuando el asistente divida una clase-dios (Manual 0, sección 4), algunas referencias del inspector pueden quedar vacías.

  • Selecciona los GameObjects afectados (HUD, jugador, generadores) y revisa que no haya campos "Missing" o vacíos en el inspector.
  • Re-arrastra las referencias a los componentes nuevos.
  • Si un componente sale como "Missing Script", es un GUID roto: usa LimpiarMissingScripts (portado de v2) o reasigna el script a mano.

8 · Input

  • Tienes InputSystem_Actions.inputactions. Abre y verifica los mapeos (movimiento, disparo, entrar/salir vehículo, bombas).
  • Project Settings → Player → Active Input Handling = Input System (New) o Both.

9 · Build final

  • File → Build Settings → PC, Mac & Linux Standalone → Windows x64.
  • Player Settings: nombre, icono, resolución, calidad por defecto = la más alta que mantenga 60 fps.
  • Build And Run. Prueba: menú → cargar mundo → conducir/andar por Alsasua.

10 · Checklist de "se ve AAA"

  • Tonemapping ACES + exposición física activados.
  • Sombras nítidas de cerca, suaves de lejos; contact shadows ON.
  • Ambient occlusion (GTAO) y screen-space reflections en superficies mojadas.
  • Niebla volumétrica sutil en el valle (Aralar al fondo).
  • LODs en todos los edificios y árboles (sin "popping" brusco).
  • Ortofoto/materiales reales en fachadas (Manual 3 y 4) → reconoces el pueblo.
  • 60 fps estables en tu GPU objetivo.
