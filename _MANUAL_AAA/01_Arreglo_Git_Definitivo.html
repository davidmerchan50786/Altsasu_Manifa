PROYECTO ALTSASU · MANIFA

MANUAL 1

Arreglo definitivo de Git / LFS
(que no se vuelva a trocear nunca)

Ejecutar en TU máquina (Windows/PowerShell o Git Bash) — NO en el contenedor

1 · El diagnóstico: por qué pasó

v2 nació de trocear el proyecto porque el repo pesaba demasiado para git. La causa raíz NO era el código, era esto:

SíntomaCausa real
.git de 211 MB en el juego, 1.2 GB en v2LFS estaba declarado en .gitattributes pero nunca se activó (no había git lfs install). Los 2.000+ binarios (png, fbx, glb...) entraron como blobs normales y se quedan en la historia para siempre.
191 MB de Cesium en el repoEl paquete Cesium está embebido en Packages/com.cesium.unity/ incluyendo 138 MB de .dylib de macOS que en Windows ni usas. Debería venir del registro, no del repo.
198 MB en _ExtractedAssetsModelos .glb pesados duplicados en Assets/Models/Misc_Extracted/ (mismo MD5).
84 MB de MapMagic, 45 MB de .REFERENCE_ONLYContenido de demo de terceros y .blend de referencia que Unity ni importa (no tienen .meta).
La regla de oro que se incumplió: en un proyecto Unity, los binarios van por Git LFS y la historia nunca debe acumular blobs gigantes. Si haces esto bien, un proyecto de 800 MB de trabajo tiene un .git de pocas decenas de MB y se clona en segundos. Entonces no hace falta trocear nada.

AntesDespués

3 · Procedimiento (paso a paso)

ESTO REESCRIBE LA HISTORIA DE GIT. Hay que hacer --force al final. Haz copia de seguridad primero (paso 0) y avisa a cualquiera que tenga clon: tras esto, deben re-clonar.

0Copia de seguridad total (innegociable)

# Clona un espejo completo por si algo sale mal
git clone --mirror https://github.com/davidmerchan50786/altsasu_manifa.git altsasu_BACKUP.git
# Y comprime también tu carpeta de trabajo actual entera (incluye assets sin commitear)

1Instalar herramientas

# Git LFS  (https://git-lfs.com)
winget install GitHub.GitLFS        # Windows
#  o:  choco install git-lfs
git lfs install

# git-filter-repo  (https://github.com/newren/git-filter-repo)
pip install git-filter-repo
#  o descarga el script y ponlo en el PATH

2Quitar Cesium embebido (lo trae el registro)

El manifest.json ya declara "com.cesium.unity": "1.23.2" desde el registro unity.pkg.cesium.com. No necesitas la copia embebida.

git rm -r --cached Packages/com.cesium.unity
# Borra también del disco la carpeta (Unity la re-descargará al abrir):
#   Windows:  rmdir /s /q Packages\com.cesium.unity
git commit -m "git: quitar Cesium embebido (se restaura desde el registro)"
Al abrir Unity tras esto, comprueba que Cesium se descarga sin error. Si tu copia estaba modificada a mano, primero anota los cambios. (No detectamos modificaciones, pero verifícalo tú).

3Quitar duplicados, demos y referencias muertas

# Duplicado exacto de modelos (mantén _ExtractedAssets, quita Misc_Extracted)
git rm -r --cached "Assets/Models/Misc_Extracted"
# Demos de MapMagic (no son el juego)
git rm -r --cached "Assets/MapMagic/Demo/Compatibility"
# .blend de referencia que Unity ni importa (sin .meta)
git rm --cached "Assets/_ExtractedAssets/Otros/forest-monster/forest-monster-final.blend.REFERENCE_ONLY"
git rm --cached "Assets/_ExtractedAssets/Animals/rooster/rooster.blend.REFERENCE_ONLY"
git rm --cached "Assets/_ExtractedAssets/Animals/chicken/chickenV2.blend.REFERENCE_ONLY"
git commit -m "git: quitar duplicados, demos de MapMagic y .blend de referencia"

El .gitignore ya se ha endurecido en la rama para que *.REFERENCE_ONLY y los generados de Cesium no vuelvan a entrar.

4Migrar binarios a LFS (en TODA la historia)

git lfs migrate import --everything \
  --include="*.png,*.jpg,*.jpeg,*.tga,*.tif,*.psd,*.exr,*.hdr,*.fbx,*.FBX,*.obj,*.glb,*.gltf,*.blend,*.wav,*.mp3,*.ogg,*.dll,*.so,*.dylib,*.a,*.raw,*.asset"
git lfs ls-files | wc -l     # debería listar miles de archivos ahora en LFS
Esto reescribe la historia moviendo los binarios a LFS. A partir de aquí, todo binario nuevo va a LFS automáticamente porque .gitattributes ya lo mapea.

5Purgar de la historia lo que ya no debe estar

# Borra de TODA la historia las rutas que quitamos (libera el peso de verdad)
git filter-repo --force \
  --path "Packages/com.cesium.unity" \
  --path "Assets/Models/Misc_Extracted" \
  --path "Assets/MapMagic/Demo/Compatibility" \
  --path-glob "*.REFERENCE_ONLY" \
  --invert-paths

6Compactar

git reflog expire --expire=now --all
git gc --prune=now --aggressive
du -sh .git        # comprobar que ha bajado mucho

7Subir (force) y reconectar el remoto

# filter-repo quita el remoto por seguridad; vuelve a añadirlo:
git remote add origin https://github.com/davidmerchan50786/altsasu_manifa.git
git push origin --force --all
git push origin --force --tags
Cualquier otro clon (incluido el contenedor de la nube) queda obsoleto tras el force-push. Hay que re-clonar, no hacer pull.

4 · Cómo NO repetir el error (prevención)

ReglaCómo
LFS siempre activogit lfs install en cada máquina nueva. Verifica con git lfs status antes de commitear binarios.
Nunca embeber paquetes del registroSi está en manifest.json, NO debe estar en Packages/ como carpeta.
Nada de demos de asset store en gitLas carpetas Demo/, Example/, Sample/ de paquetes de terceros se pueden ignorar.
Revisar antes de commitearSi vas a meter > 5 MB en un commit no-LFS, párate y revisa.
Un solo repoCon LFS no hay motivo para trocear. Si vuelve a pesar, es que LFS no está activo: revísalo, no trocees.

5 · Qué dejó hecho el asistente (sin reescribir historia)

Desde el contenedor no hay git-lfs/filter-repo y reescribir+force a ciegas es peligroso. Lo que SÍ se ha dejado commiteado de forma segura en la rama:

  • .gitignore endurecido: ignora *.REFERENCE_ONLY, generados de Cesium, carpetas de recovery/staging.
  • Confirmado que .gitattributes tiene las reglas LFS correctas (solo faltaba activarlas — paso 1 y 4).
  • Este manual.

Los pasos 2–7 los ejecutas tú en local porque implican reescritura de historia + force-push, que deben hacerse donde puedas verificar en Unity que todo sigue abriendo bien.
